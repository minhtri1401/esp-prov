# esp_prov: Pure-Dart ESP Unified Provisioning Library — Design

- Date: 2026-10-05
- Status: approved design, awaiting spec review
- Replaces: pub.dev `flutter_esp_ble_prov` 0.1.7 (abandoned Feb 2024, different publisher)
- Facts reference: [docs/research/2026-10-05-esp-provisioning-facts.md](../../research/2026-10-05-esp-provisioning-facts.md)

## 1. Goal

A modern, cross-platform Flutter/Dart library that provisions Espressif devices
over BLE using Espressif's Unified Provisioning protocol (protocomm), with full
Security 0/1/2 support implemented in pure Dart, Wi-Fi and Thread flows, and
custom endpoints. It must work with firmware from ESP-IDF 5.1 through 6.x,
including both the legacy `wifi_provisioning` component and its successor
`network_provisioning`.

### Success criteria

1. Provisions the user's ESP32-S3-DevKitC-1 running the stock `wifi_prov_mgr`
   example with Security 2, from Android and iOS, end to end (scan, connect,
   handshake, Wi-Fi scan, set credentials, observe `Connected`).
2. Security 0, 1 and 2 handshakes and ciphers pass unit tests against fixtures
   generated by Espressif's own `esp_prov` Python modules.
3. `esp_prov_core` has zero Flutter imports and scores 160 pub points with all
   six platforms detected.
4. Wrong password, unknown SSID, PoP mismatch and device disconnect each
   surface as a distinct typed error. No nullable booleans in the public API.
5. Custom endpoint round trip (`custom-data`) works against the example firmware.

### Out of scope for v1

- SoftAP (HTTP) transport. The transport interface is designed so it can be
  added in v1.1 without changing the core.
- Adapters for BLE libraries other than `universal_ble`.
- Peripheral-side or firmware code beyond the stock example used for testing.
- QR code scanning UI. We parse the QR payload JSON; the app supplies the string.

## 2. Decisions and rationale

| Decision | Choice | Why |
|---|---|---|
| Implementation strategy | Pure Dart protocol stack, pluggable transport | Six platforms, hardware-free tests, no native SDK churn. No Dart package offers Security 2 today. |
| BLE backend | `universal_ble` ^2.2 only | BSD-3, 160 pub points, six platforms, Pigeon-based, 0x2901 descriptor reads since 2.2.0. `flutter_blue_plus` 2.x is proprietary and forces a license enum on callers. `flutter_reactive_ble` cannot read descriptors. |
| Protobuf source | `network_provisioning` protos (network_*.proto) plus protocomm protos | Wire-compatible superset of the old `wifi_*.proto`, adds Thread. One schema set covers all firmware versions. |
| Crypto | `cryptography_plus` for X25519/AES-CTR/AES-GCM, `crypto` for SHA-256/512, hand-written SRP-6a on `BigInt` | No pub.dev package implements Espressif's SRP-6a profile (3072-bit, g=5, SHA-512, RFC 2945 proofs). pointycastle's SRP uses different M1/M2 formulas. |
| Package names | `esp_prov_core`, `esp_prov_ble_universal`, `esp_prov` | `flutter_esp_ble_prov` is owned by another publisher. Follow-up: ask the old author to add a deprecation note pointing to `esp_prov`. |
| Repo shape | Pub workspace monorepo | Shared tooling, atomic cross-package changes, independent publishing. |
| Minimum SDK | Dart ^3.13, Flutter ^3.47 | Current stable. Sealed classes, records, patterns, primary constructors. |

## 3. Architecture

```
┌──────────────────────────────────────────────────────────────┐
│ esp_prov (Flutter)                                           │
│   EspProvisioning.scan() -> Stream<EspDevice>                │
│   EspDevice.connect() -> EspSession                          │
│   re-exports core types                                      │
├──────────────────────────────────────────────────────────────┤
│ esp_prov_ble_universal (Flutter)                             │
│   UniversalBleScanner  implements ProvScanner                │
│   UniversalBleTransport implements ProvTransport             │
├──────────────────────────────────────────────────────────────┤
│ esp_prov_core (pure Dart)                                    │
│   flows/     WifiProvisioner, ThreadProvisioner, ProvCtrl,   │
│              CustomEndpoint                                  │
│   session/   EspSession (proto-ver, scheme selection,        │
│              handshake, encrypted request wrapper)           │
│   security/  SecurityScheme sealed: Security0/1/2            │
│   crypto/    Srp6aClient, AesCtrStream, AesGcmCounter        │
│   transport/ ProvTransport, ProvScanner interfaces           │
│   proto/     generated protobuf (protocomm + network_*)      │
│   qr/        ProvQrPayload parser                            │
└──────────────────────────────────────────────────────────────┘
```

Dependencies point downward only. The core never imports Flutter or
`universal_ble`.

### 3.1 Transport layer (core)

```dart
abstract interface class ProvTransport {
  /// Endpoint names discovered on the device, e.g. {'prov-session', 'prov-config', 'custom-data'}.
  Set<String> get endpoints;
  /// Sends [request] to [endpoint] and returns the device's response bytes.
  Future<Uint8List> send(String endpoint, Uint8List request);
  /// Emits once when the link drops for any reason.
  Stream<void> get onDisconnected;
  Future<void> disconnect();
}

abstract interface class ProvScanner {
  Stream<DiscoveredDevice> scan({String namePrefix = 'PROV_'});
}

abstract interface class DiscoveredDevice {
  String get id;        // platform device id
  String get name;      // advertised name
  int? get rssi;
  String get serviceUuid;  // 128-bit, from the advertisement
  Future<ProvTransport> connect();
}
```

One transaction = one `send`. The BLE adapter implements `send` as
write-with-response followed by a read of the same characteristic, serialised
through a queue so two flows cannot interleave on the link.

### 3.2 BLE adapter (`esp_prov_ble_universal`)

- Scan: filter by advertised name prefix (case-insensitive). Take the primary
  service UUID from `serviceUuids[0]` in the advertisement. Deduplicate by id.
- Connect: connect, request MTU 512 (Android only path; no-op elsewhere),
  discover services, pick the advertised service UUID (fall back to the
  firmware default `1775244d-6b43-439b-877c-060f2d9bed07` and then to the only
  non-standard service if exactly one exists).
- Endpoint discovery: for each characteristic read the 0x2901 descriptor and
  map its lowercased string value to the characteristic. If a characteristic
  has no 0x2901 descriptor, derive the name from UUID bytes 12-13 via the known
  table (FF4F ctrl, FF50 scan, FF51 session, FF52 config, FF53 proto-ver).
  Custom endpoints without a descriptor remain unaddressable and are reported
  in a `warnings` list.
- Transaction: `write(withResponse: true)` then `read`. Payload size is bounded
  by the firmware (256 B Bluedroid, 480 B with Security 2, 512 B NimBLE); the
  adapter does not chunk. Core flows keep requests small (scan pages of 4).
- Disconnect: surface `universal_ble` connection-state changes on
  `onDisconnected`.
- Permissions: the adapter does not request runtime permissions. The README
  documents required manifest entries and recommends `permission_handler`.
  Rationale: the old package's self-managed permissions caused crashes and
  blocked apps from controlling the UX.

### 3.3 Security layer (core)

```dart
sealed class SecurityScheme {
  Future<void> handshake(ProvTransport t);   // on 'prov-session'
  Uint8List encrypt(Uint8List plain);
  Uint8List decrypt(Uint8List cipher);
}
final class Security0 extends SecurityScheme { ... }   // identity cipher
final class Security1 extends SecurityScheme { Security1({String? pop}); }
final class Security2 extends SecurityScheme { Security2({required String username, required String password, required int patchVersion}); }
```

Security 1 facts enforced by the implementation:
- X25519 ephemeral keypair; `SessionCmd0{client_pubkey}` → `SessionResp0{device_pubkey, device_random}`.
- Key = X25519 shared secret XOR SHA-256(PoP) bytewise when a PoP is set.
- AES-256-CTR with IV = `device_random`, one continuous keystream shared by
  encrypt and decrypt for the whole session (`AesCtrStream` tracks offset).
- `SessionCmd1{client_verify_data = ctr(device_pubkey)}`; response
  `device_verify_data` decrypts to the client public key or the handshake
  fails with `PopMismatch`.

Security 2 facts enforced by the implementation:
- SRP-6a, RFC 5054 3072-bit group, g=5, SHA-512. `A` must serialise to exactly
  384 bytes; re-roll `a` otherwise.
- `x = H(s | H(I ":" p))`, `k = H(N | PAD(g))`, `u = H(PAD(A) | PAD(B))`,
  `S = (B − k·g^x)^(a + u·x) mod N`, `K = H(S)` (64 bytes),
  `M1 = H(H(N) ⊕ H(g) | H(I) | s | A | B | K)`, `M2 = H(A | M1 | K)`.
- Reject `B ≡ 0 mod N` or `u = 0`.
- AES-256-GCM key = `K[0..32]`, 16-byte tag appended, no AAD.
- Nonce = `device_nonce` (8-byte session id + 4-byte big-endian counter starting at 1).
  `patchVersion == 1`: increment the counter after every encrypt and every
  decrypt (one shared counter). `patchVersion == 0`: fixed nonce (legacy
  firmware before the 2025 fix).
- All `modPow` work runs inside `Isolate.run` so the UI thread never blocks.
  Web has no isolates; there the computation runs inline and is documented as
  taking longer.

Scheme selection happens in the session from `proto-ver`, never by caller
guess. The caller supplies credentials (`pop`, or `username`+`password`); the
library picks the scheme the firmware declares.

### 3.4 Session layer (core)

```dart
final class EspSession {
  static Future<EspSession> open(ProvTransport t, {ProvCredentials? credentials});
  DeviceInfo get info;          // ver, secVer, secPatchVer, capabilities, appInfo
  Future<Uint8List> request(String endpoint, Uint8List body); // encrypt → send → decrypt
  WifiProvisioner get wifi;     // throws UnsupportedCapability only if caps list thread_prov without wifi_prov
  ThreadProvisioner get thread; // requires cap.threadProv
  ProvCtrl get ctrl;
  CustomEndpoint custom(String name);
  Stream<void> get onDisconnected;
  Future<void> close();
}
```

`open` flow:
1. Write any byte to `proto-ver`, parse JSON. Missing `prov.sec_ver` → 1.
   Missing `sec_patch_ver` → 0. Parse `cap` list and any extra app-info keys.
2. Choose scheme: `sec_ver` 0 → Security0; 1 → Security1 (PoP optional if
   `no_pop`); 2 → Security2 (username+password required, else
   `MissingCredentials`).
3. Run handshake on `prov-session`.
4. Return the session. Every later `request` is serialised through one queue
   because Security 1 and 2 ciphers are stateful and order-dependent.

### 3.5 Flows (core)

**WifiProvisioner**
- `scan({bool passive = false, int groupChannels = 0, int periodMs = 120})`:
  `CmdScanWifiStart{blocking: true}` → poll `CmdScanWifiStatus` every 500 ms
  until `scan_finished` → page `CmdScanWifiResult` with `count = 4` →
  `List<WifiNetwork>` sorted by RSSI, deduplicated by SSID keeping the
  strongest.
- `provision({required String ssid, required String passphrase, Uint8List? bssid, int? channel, Duration timeout = 30s, Duration pollInterval = 1s})` →
  `Stream<WifiProvisionState>` emitting `Applying`, `Connecting`,
  `AttemptFailed(attemptsRemaining)`, then exactly one terminal:
  `Connected(ip4, authMode, ssid, bssid, channel)` or
  `Failed(reason: AuthError | NetworkNotFound | Timeout)`. Internally:
  `CmdSetWifiConfig` → `CmdApplyWifiConfig` → poll `CmdGetWifiStatus`.
- A transport disconnect after `Connected` has been emitted is swallowed
  (firmware auto-stop). A disconnect before that becomes
  `Failed(DeviceDisconnected)`.

**ThreadProvisioner**
- `scan()`: `CmdScanThreadStart{blocking: true}` → status → paged results →
  `List<ThreadNetwork>`.
- `provision({required Uint8List datasetTlvs})` → `Stream<ThreadProvisionState>`
  with `Attached`/`Failed(DatasetInvalid | ThreadNetworkNotFound)`.

**ProvCtrl**
- `resetWifi()`, `reprovisionWifi()`, `resetThread()`, `reprovisionThread()`.
  Each returns `void` or throws `ProvStatusException(status)`.

**CustomEndpoint**
- `Future<Uint8List> send(Uint8List data)`; throws `UnknownEndpoint` if the
  transport did not discover the name.

### 3.6 Public API (`esp_prov`)

```dart
final prov = EspProvisioning();                       // uses UniversalBle by default
await for (final d in prov.scan(namePrefix: 'PROV_')) { ... }

final session = await d.connect(
  credentials: ProvCredentials.security2(username: 'wifiprov', password: 'abcd1234'),
  // or ProvCredentials.pop('abcd1234'), or ProvCredentials.none()
);
final networks = await session.wifi.scan();
await for (final s in session.wifi.provision(ssid: ..., passphrase: ...)) {
  switch (s) {
    case WifiConnected(:final ip4): ...
    case WifiFailed(:final reason): ...
    default: ...
  }
}
await session.close();

final qr = ProvQrPayload.parse(jsonString); // ver, name, pop, transport, security, username, password, network
```

`ProvCredentials` is a sealed class with `none`, `pop`, `security2`. If the
firmware's `sec_ver` does not match the credential kind, `connect` throws
`SchemeMismatch(expected, provided)` with a message telling the developer what
the device wants.

### 3.7 Error model

```dart
sealed class ProvException implements Exception { String get message; }
final class TransportException extends ProvException     // BLE failures, timeouts
final class DeviceDisconnected extends ProvException
final class UnknownEndpoint extends ProvException
final class UnsupportedCapability extends ProvException
final class SchemeMismatch extends ProvException
final class MissingCredentials extends ProvException
final class HandshakeFailed extends ProvException        // generic, carries Status
final class PopMismatch extends HandshakeFailed          // Sec1 verify failure / Sec2 proof failure
final class CryptoException extends ProvException        // GCM tag failure etc.
final class ProvStatusException extends ProvException    // non-Success Status from device
```

Provisioning outcomes (wrong password, network not found) are states in the
result stream, not exceptions, because they are expected user-facing results.

## 5. Testing strategy

| Layer | Approach |
|---|---|
| crypto/ | Fixtures from `esp_prov` Python: SRP-6a with fixed `a`, salt, verifier → expected A, M1, M2, K; AES-GCM nonce sequences; Sec1 with fixed keypairs → verify data. Property test: encrypt→decrypt round trips. |
| security/ | Fake transport that replays recorded `prov-session` exchanges, including failure statuses. |
| session/ | proto-ver JSON variants: legacy `v1.1` without `sec_ver`, `netprov-v1.2` with Thread caps, missing `sec_patch_ver`, extra app-info keys. |
| flows/ | Scripted fake device: scan pagination, `Connecting` → `Connected`, `AttemptFailed` → `AuthError`, disconnect-after-connected swallowed, timeout. |
| ble adapter | Contract test against a fake `UniversalBle` instance via `UniversalBle.setInstance`: UUID→name mapping, descriptor fallback, write-then-read queueing. |
| example app | `integration_test` run manually against the ESP32-S3 board for Sec1 and Sec2 firmware builds. Documented checklist in `docs/`. |

Pure Dart tests use `package:test` and `mocktail`. No test depends on
hardware or on Flutter bindings except the adapter contract test.

## 6. Firmware for integration testing

Target: ESP32-S3-DevKitC-1 N16R8. Use ESP-IDF 5.4 or 6.0
`examples/provisioning/wifi_prov_mgr` (6.0 pulls `network_provisioning`
automatically). Three builds, flashed in turn:

1. Security 2 with username `wifiprov`, password `abcd1234` (default example).
2. Security 1 with PoP `abcd1234` (`CONFIG_EXAMPLE_PROV_SECURITY_VERSION_1`).
3. Security 2 with `CONFIG_WIFI_PROV_AUTOSTOP_TIMEOUT` raised and a
   `custom-data` endpoint (the example already registers one).

The example advertises as `PROV_xxxxxx` and prints a QR payload JSON to the
serial console that the example app can paste.

## 7. Risks and mitigations

| Risk | Mitigation |
|---|---|
| SRP-6a subtle mismatch with firmware (padding, byte lengths) | Byte-exact fixtures from Espressif's Python; test A must be 384 bytes; compare M1 bit for bit. |
| `BigInt.modPow` slow on low-end phones (3072-bit) | Run in `Isolate.run`; measure on device; target under 1 s AOT. |
| `universal_ble` 3.0.0 breaking release | Pin `^2.2.0`; adapter is a thin package so migration is isolated. |
| Firmware payload limit (256 B) with long SSIDs/passphrases | `CmdSetWifiConfig` max is 32 + 64 + 6 bytes plus overhead, within limit. Validate lengths client-side and throw `ArgumentError` early. |
| iOS does not expose MTU negotiation | Rely on CoreBluetooth long writes; firmware supports prepare-write. Verified by the Espressif iOS app doing the same. |
| Web Bluetooth lacks descriptor reads in some browsers | Fall back to UUID-table mapping; document that custom endpoints need descriptor support. |

## 8. Delivery phases (input to the implementation plan)

1. Workspace scaffold, vendored protos, codegen, CI (analyze, test, format).
2. Core: transport interfaces, crypto primitives with fixtures, Security 0/1/2.
3. Core: session (proto-ver, scheme selection), flows (Wi-Fi, Thread, ctrl, custom), QR parser, error model.
4. BLE adapter on `universal_ble` with contract tests.
5. `esp_prov` facade, example app, README and API docs, hardware verification.
6. Publish dry-run, verified-publisher setup, CHANGELOGs.

Phases 2 and 4 are independent and can run in parallel after phase 1.
